# FacetCue for Blender 使用与实现说明

适用版本 **0.5.2** · 许可证 **GPL-3.0-or-later**

**表面标注、Agent 修改与持久化审阅。**

FacetCue for Blender 将每个修改问题变成物体表面的独立标记：用自然语言写要求，用三维表面锚点指明位置。Agent 通过 MCP 批量读取这些要求与位置，调用已连接的 Blender 建模工具逐项修改，再提交完成说明。用户按标记审核，待处理、进行中、待审核和已完成等状态分别记录；保存 `.blend` 后可在下次打开时接续审阅。

标记是视口叠加显示，不会为渲染或常规模型导出添加圆点、文字等对象。用户可以开关显示，agent 始终可以读取已确认的注释；注释随 `.blend` 保存，因此“渲染中不可见”不代表文件中没有这些数据。

## 安装与连接

### 环境和安装包

| 项目 | 要求或用途 |
| --- | --- |
| Blender | 4.2 或更新版本；本版已在 Windows 的 Blender 5.2.1 LTS 验证 |
| macOS 与 Linux | 使用同一份源码和安装包，运行表现仍需实机验证 |
| 插件本体 | 只使用 Blender API 和 Python 标准库，不需要额外安装 Python 依赖 |
| MCP 配套服务 | 独立 Python 3.10+ 环境，以及支持 stdio MCP 的 agent 客户端 |
| `facetcue-0.5.2.zip` | 安装到 Blender 的扩展包 |
| `facetcue-0.5.2-py3-none-any.whl` | 安装到独立 Python 环境的 MCP 配套包 |
| `facetcue-0.5.2.tar.gz` | 包含源码和文档的开发用源码包 |

仅在 Blender 内使用标记时，安装 ZIP 即可。需要 agent 读取和提交时，再配置 MCP。MCP 配套包依赖 `mcp==1.29.1`，由 pip 安装；wheel 没有捆绑第三方依赖，首次安装需要能够访问软件源。

### 在 Blender 安装

1. 打开 **偏好设置 → 插件 → 从磁盘安装**，选择 ZIP，不要先解压。
2. 启用 **FacetCue for Blender**。同一时间只启用一份安装，避免旧式插件目录与扩展目录重复启用。
3. 在 3D 视口按 **N**，打开 **FacetCue for Blender → 表面注释**。
4. 确认面板显示“Agent 连接已就绪”。这表示 Blender 本机接口已启动；客户端配置完成后，agent 才能调用它。

### 安装 MCP 配套服务

在存放 wheel 的目录执行以下命令。使用独立环境，不向 Blender 内置 Python 安装依赖，也不需要激活虚拟环境。

Windows PowerShell：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\facetcue-0.5.2-py3-none-any.whl
```

macOS 或 Linux：

```sh
python3 --version
python3 -m venv .venv
./.venv/bin/python -m pip install ./facetcue-0.5.2-py3-none-any.whl
```

### 配置 agent 客户端

为客户端添加一个 stdio MCP 服务：`command` 使用上述环境中 Python 的**绝对路径**，`args` 使用 `-m agent_mcp.server`。采用 TOML 配置的客户端可参考：

```toml
[mcp_servers.facetcue]
command = 'C:/path/to/.venv/Scripts/python.exe'
args = ['-m', 'agent_mcp.server']
```

macOS 与 Linux 将 `command` 换成实际的 `/absolute/path/to/.venv/bin/python`。其他客户端按其配置格式填写相同的命令和参数。完整模板见 [MCP 配置示例](../examples/codex-mcp.example.toml)。

重新加载客户端的 MCP 配置，保持 Blender 和插件开启。客户端应能发现两个工具：

- `get_surface_annotations`：读取注释与位置。
- `submit_annotation_changes`：把实际完成的修改提交为待审核。

首次调用 `get_surface_annotations()` 不需要任何参数，也不需要选择物体、保存文件、执行 Blender Python 或提供截图。成功查询后，插件面板会显示最近 MCP 查询时间与读取条数。没有标记时，成功返回的总数可以为零；连接失败会明确报错。

只有一个 Blender 实例时自动发现。多个实例同时运行时，在同一 MCP 配置中增加：

```toml
[mcp_servers.facetcue.env]
ASM_INSTANCE = '替换为目标 Blender 面板显示的 32 位实例 ID'
```

实例 ID 对应本次插件连接会话，重启 Blender 或重新启用插件后会重新生成；固定了 ID 的客户端需要同步更新。只使用一个实例时，可移除该配置恢复自动发现。本机接口自动分配端口和认证令牌，无需手动填写。

## 放置和编辑注释

### 第一个标记

1. 切换到 **物体模式**和**实体显示**，确认目标为可标注的基础网格，不必预先选中物体。
2. 打开 Blender 的**显示叠加层**，同时启用面板中的“显示表面标记”。
3. 点击“在表面添加注释”，或按 **Ctrl+Alt+Shift+A**，然后点击模型表面。放置期间可以旋转视图，**Esc / 右键**取消放置。
4. 在自动获得输入焦点的紧凑注释框中填写要求，按 **Enter** 保存并关闭。新建时必须填写非空内容；取消不会留下空标记。
5. 标记显示独立颜色和数字，列表中使用 `M0001` 这样的编号。确认后 agent 立即可读；需要跨次打开保留时，正常保存 `.blend`。

注释宜同时说明修改动作和需要保留的条件，例如：“把面板沿 Z 轴上移 0.12 个 Blender 单位，保持形状和尺寸不变。”位置由标记提供，文字负责说明意图和验收条件。

### 紧凑弹窗和多行编辑

单击标记选中；双击编号，或点击列表中的铅笔，可编辑已有注释。

紧凑弹窗默认位于视口中下部，拖动最上方标题即可移动。新增、编辑和打回共用最近的位置，重启 Blender 后仍保留。位置按视口比例记录在 Blender 用户配置目录的 `agent_marks_ui.json` 中，与场景分开保存。弹窗会受当前视口尺寸约束。

| 编辑方式 | 确认 | 换行 | 取消或关闭 |
| --- | --- | --- | --- |
| 默认紧凑弹窗 | Enter 保存并关闭 | 默认单行输入 | Esc 取消当前草稿，保留原注释 |
| 主动打开的多行编辑器 | Enter 保存并返回模型 | Shift+Enter | Esc 放弃草稿；直接关闭独立窗口则保留草稿供继续编辑 |

需要长文时，先保存标记，再从侧栏点击“多行编辑”。已有多行内容默认以紧凑预览打开，点击“展开多行编辑”才进入独立的 Blender 文本窗口；不会自动把多行内容压成单行。独立窗口的尺寸和位置由 Blender 管理，不使用紧凑弹窗的位置记忆。

正文最长 **8000 字符**，支持中文。视口卡片和侧栏可能截短显示，agent 读取的是完整正文。尚未确认的草稿不发送给 agent。

## 查看标记并定位或删除

### 显示与 X-Ray

普通实体视图只显示未被几何遮挡的标记。**Alt+Z** 切换的是 X-Ray 穿透显示，与透视投影或正交投影的切换不同。

| 状态 | 标记表现 |
| --- | --- |
| 普通视图中直接可见 | 显示标记，选中后可查看注释卡片 |
| 普通视图中被遮挡 | 隐藏标记 |
| X-Ray 中直接可见 | 保持正常不透明度 |
| X-Ray 中被遮挡 | 使用 **60% 透明度，即 40% 不透明度** |
| X-Ray 中的注释卡片 | 默认折叠，可在面板启用“展开 X-Ray 注释” |
| 已修改并等待审核 | 主标记颜色不变，右上角出现带窄白边的蓝点 |

编号、主标记和状态蓝点采用相同的遮挡与透明度规则。当前只有待审核状态显示这个状态点；未处理、通过或打回不会添加其他颜色的状态点。

X-Ray 不会强制显示隐藏对象、画面外、裁剪范围外或锚点失效的标记。显示还受插件开关、Blender 叠加层开关及面板筛选影响。**这些显示条件都不限制 agent 读取已确认的注释。**

新建时会检查当前文件各场景已有标记的颜色，避免 8 位 RGB 重复并优先选择差异较大的颜色。大量标记仍应结合编号识别，不能只依赖肉眼分辨颜色。

### 搜索与定位

面板支持按编号、正文和目标物体名称搜索，并按待处理、待审核、已打回、已完成或已归档筛选。

点击“定位”、列表放大镜或“上一个 / 下一个”，会靠近观察匹配的标记，并把视角旋转中心移到注释点。观察距离依据目标物体尺寸估算，不改变模型选择。隐藏目标需先恢复可见；位置失效时，定位可能只能给出创建时的参考位置，应先处理面板的位置提示。

### 删除归档和撤销

选中标记，点击“删除当前标记”或按 **Ctrl+Alt+Shift+X**。核对确认框中的编号后再确认。删除会移除该标记、注释及其审核历史，不改变模型；agent 的后续读取也不再包含它。按 **Ctrl+Z** 可撤销删除。

归档会隐藏标记绘制，但保留内容供 agent 读取。可在“已归档”筛选中选择并重新打开。删除不会自动回收已使用的编号。

UI 编辑和删除使用 Blender 的 **Ctrl+Z / Ctrl+Shift+Z** 撤销与重做。审核专用“撤回”则只恢复最近一次通过或打回之前的注释、审核状态和修改说明，不撤销模型操作。

### 快捷键速查

以下插件快捷键用于**物体模式的 3D 视口**。先完成或取消文字输入，再将鼠标移回视口使用。

| 默认组合 | 功能 |
| --- | --- |
| Ctrl+Alt+Shift+M | 开关标记显示与点选 |
| Ctrl+Alt+Shift+A | 放置标记 |
| Ctrl+Alt+Shift+← | 上一个匹配标记并定位 |
| Ctrl+Alt+Shift+→ | 下一个匹配标记并定位 |
| Ctrl+Alt+Shift+Enter | 通过当前待审核标记 |
| Ctrl+Alt+Shift+Backspace | 打回当前待审核标记并编辑要求 |
| Ctrl+Alt+Shift+Z | 撤回最近一次通过或打回 |
| Ctrl+Alt+Shift+X | 确认删除当前标记 |

插件注册时检查相关 Blender 键位，跳过检测到的冲突并在面板提示。自定义键位或系统级热键仍可能占用组合，可使用面板按钮或调整 Blender 键位设置。macOS 的 Option 对应 Alt，Control 不替换成 Command。

## 与 agent 协作和审核

### 一次完整协作

1. **用户写要求**：为每个问题放置独立标记，确认自然语言正文。新标记为“待处理”。
2. **Agent 批量读取**：调用 `get_surface_annotations()`，读取多条问题，检查各自的要求、ID、修订号、目标物体、有效位置及可见性；有更多记录时继续分页。
3. **Agent 逐项修改模型**：按用户指定的范围，通过已连接的 Blender 建模工具自动执行修改，并用标记 ID 对应每项结果。这个注释 MCP 本身不提供建模命令。
4. **Agent 提交完成**：实际完成后调用 `submit_annotation_changes()`，只提交已完成的相关标记，并说明修改内容。插件把状态改为“已修改 · 待审核”，显示蓝点。
5. **用户审核**：筛选“待审核”，逐项定位，查看模型和“Agent 修改说明”，选择通过或打回。
6. **继续迭代**：打回时在紧凑框中补充要求，Enter 确认后变为“已打回”。Agent 重新读取新的要求与修订号，修改后再次提交。

插件不会把任意模型变化自动判为 agent 已完成。蓝点表示**完成提交已记录**，不表示修改已经通过用户验收。打回输入按 Esc 取消时，保留原待审核状态。

| API 状态 | 含义和常见入口 |
| --- | --- |
| `OPEN` | 待处理；新建或重新打开 |
| `IN_PROGRESS` | 进行中；可在面板手动设置 |
| `MODIFIED` | 已修改、待审核；agent 完成提交 |
| `RESOLVED` | 已通过；审核通过，或用户手动“完成” |
| `CHANGES_REQUESTED` | 已打回；用户确认新的修改要求 |
| `ARCHIVED` | 已归档；隐藏绘制并保留记录 |

审核撤回保存每个场景最近最多 100 次通过或打回记录。如果该标记在审核后又被编辑，撤回会拒绝覆盖较新的内容。手动“完成”“归档”等状态操作不属于这份审核历史，可使用普通 Blender 撤销。

### 保存后继续审阅

在 Blender 中保存 `.blend`，标记与目标物体的关联、表面锚点、正文、状态、修订号、最近一次 Agent 修改说明及保留的审核记录会一起保存。重新打开文件并启用插件后，用户可以继续定位和审核，Agent 也可以重新读取待处理或已打回的问题。

这份记录描述每个问题的修改说明和审核决定；几何结果随场景本身保存。它不记录每一步建模命令，也不代替模型版本管理。若目标网格的拓扑变化，重新读取时仍需检查锚点是否有效。

### Agent 的调用约定

默认读取当前文件**所有场景、所有状态**，每页 50 条；`limit` 可设为 1–200。存在 `has_more=true` 时，将返回的 `next_offset` 作为下一次的 `offset` 继续读取。每一页都是一次实时读取，不是冻结的整文件快照。可通过 `scene_name` 限定场景，通过 `include_visibility=false` 省略视口计算。

提交工具的参数形式如下。`Scene`、示例 ID 和修订号 `1` 均需替换为修改前实际读取的值；`marker_id` 使用记录的 `id`，不是可见编号 `M0001`。

```json
{
  "changes": [
    {
      "scene_name": "Scene",
      "marker_id": "从读取结果复制的 id",
      "expected_revision": 1,
      "summary": "已将面板沿 Z 轴上移 0.12 个 Blender 单位，形状和尺寸保持不变。"
    }
  ]
}
```

每次可提交 1–200 条。插件先验证整批再写入状态；完成说明不覆盖用户注释，也不改变标记本体颜色。同一修订号与说明的重复提交可安全重试；遇到 `REVISION_CONFLICT` 应重新读取并核对要求，不能直接覆盖。模型修改后也应重新读取，检查锚点是否仍有效。

支持 MCP 资源的客户端还可访问 `blender-marks://current`，它执行相同的默认读取。详细字段和 Blender 内部开发接口见 [API 说明](api.zh-CN.md)。

## 实现方式与数据

### 连接链路

```text
Agent 客户端
  → stdio MCP → agent_mcp.server（独立 Python）
  → 127.0.0.1 上的认证接口 → Blender 主线程
  → 读取注释或记录完成提交
```

这条链路不依赖其他 Blender MCP，也不执行传入的 Python。现有建模工具可以与它并行配置，负责实际几何编辑。本机接口只接受连接探测、注释读取和完成提交；没有远程监听、删除、审核通过或任意代码执行入口。

插件启用时产生随机端口、随机令牌和用户临时目录中的连接描述文件；关闭插件时移除当前描述文件。所有 `bpy` 数据访问在 Blender 主线程执行，连接轮询限制请求大小、处理时间和并发量。

### 注释如何附着和保存

正式标记存储在专用 **Text 数据块**的 `asm_*` 属性中，不放在可导出的 Scene、Object 或 Mesh 自定义属性上。它包含场景与对象关联、稳定 UUID、显示编号、颜色、正文、任务状态、修订号、时间和审核记录。草稿使用独立 Text 数据块，作为文字保存，不作为脚本执行。

锚点记录基础网格的三角形、顶点索引、重心坐标和拓扑指纹。读取时结合当前顶点坐标与对象变换重新计算局部位置、世界位置和法线。对象移动或拓扑保持一致的顶点调整可跟随；拓扑或三角化改变时需要重新校验，不会凭旧坐标猜测新的表面。

视口使用 GPU 叠加绘制圆点、编号、注释卡片和状态点，通过投影及几何射线判断屏幕位置和遮挡。几何查询采用有界缓存并随相关更新失效，MCP 读取重新获取当前数据，不依赖上一次屏幕绘制结果。

| 信息类别 | 主要字段或约定 |
| --- | --- |
| 注释身份 | `id` 为稳定 UUID；`label` 为显示编号；`revision` 用于并发修改校验 |
| 用户要求与审核 | `note`、`status`、`review.change_summary`、`status_badge` |
| 表面位置 | `anchor` 保存附着依据；`resolved` 返回当前位置、法线和对象矩阵 |
| 场景单位 | 配合场景的 `unit_system`、`unit_scale_length` 解读，不能一律当作米 |
| 视口信息 | `viewport` 和顶层 `viewports` 包含可见性、屏幕坐标、区域尺寸及视图信息 |
| 屏幕坐标 | `screen_px` 以视口 WINDOW 区域左下角为原点；`screen_uv_top_left` 从左上角归一化 |

任务状态、锚点有效性和视口可见性是三类不同信息。即使标记处于“待审核”，其锚点也可能因拓扑变化失效。位置失效时返回明确原因与空的当前位置，仍保留注释；没有可用视口时仍可读取正文和有效三维位置。

`overlay_drawn` 表示按当前条件应当绘制，不保证它没有被弹窗或其他窗口盖住。截图与 JSON 也不是同一帧的原子快照。处理图像点击时应使用当前视口信息，不能直接把局部坐标当作整窗坐标。

已确认注释无需先保存文件就能被读取；要保留到下次打开，仍需保存 `.blend`。插件和 MCP 写入不会替用户自动保存文件。插件本身没有云服务或遥测，agent 读取后的数据处理由对应客户端决定，详见 [安全说明](../SECURITY.md)。

### 主要源码入口

| 模块 | 职责 |
| --- | --- |
| `core.py` | 数学、验证、颜色及状态定义 |
| `runtime.py`、`api.py` | Blender 数据注册、持久化与数据操作 |
| `viewport.py`、`spatial.py` | 投影、拾取、遮挡、空间查询与定位 |
| `ui.py`、`ux.py`、`shortcuts.py` | 绘制、面板、选择、筛选和快捷键 |
| `editor.py`、`compact.py`、`floating.py` | 注释草稿、紧凑弹窗和多行编辑 |
| `review.py` | 完成提交、审核和带修订校验的撤回 |
| `connection.py`、`protocol.py` | 本机认证连接和共享协议常量 |
| `agent_mcp/` | 独立的 stdio MCP 服务、实例发现和传输 |

开发时保留持久化字段、公开操作名和状态枚举顺序；UI 操作负责 Blender Undo，直接 API 写入不自动创建 Undo 步骤。开发与发布构建命令见 [CONTRIBUTING](../CONTRIBUTING.md)，工具契约见 [live_mcp_tools.json](../contracts/live_mcp_tools.json)。

## 当前限制与问题处理

标记附着目前支持**无启用视口修改器、无形态键的基础 Mesh**。曲线、文字和实例不能作为附着目标，但可以参与遮挡判断。放置要求物体模式、实体显示、单视图，并关闭 Alt+B 自定义视图裁剪。

删除或替换目标网格、改变拓扑等情况可能使位置失效；当前没有自动重附着功能。保留原注释，在有效表面重新建立标记后再处理旧记录。复制场景不会自动复制注释。

| 现象 | 检查或处理 |
| --- | --- |
| 看不到标记 | 打开“显示表面标记”和 Blender“显示叠加层”；清除搜索及状态筛选，检查对象隐藏、归档、遮挡和位置提示 |
| 某些角度下点消失 | 普通视图会隐藏被遮挡点；用 Alt+Z 检查。画面外、裁剪外和失效锚点仍不会显示 |
| 无法放置 | 切回物体模式、实体显示与单视图，关闭 Alt+B 裁剪，并检查目标是否为受支持的基础网格 |
| 输入后 agent 仍读到旧文 | Enter 确认注释，再重新读取；草稿和被取消的编辑不会发送 |
| `BLENDER_UNAVAILABLE` | 确认 Blender 与插件运行、面板连接就绪，并检查固定的实例 ID 是否已过期 |
| `MULTIPLE_BLENDER_INSTANCES` | 配置 `ASM_INSTANCE` 指向目标面板中的实例 ID |
| `BLENDER_BUSY_OR_TIMEOUT` | 等待 Blender 恢复响应再重试；多个实例时明确指定目标 |
| 快捷键没有反应 | 将鼠标移到物体模式的 3D 视口，退出输入或放置状态，并查看面板的快捷键冲突提示 |
| 待审核蓝点没有出现 | 确认 agent 已成功调用完成提交工具，并检查显示与筛选条件；仅移动模型不会触发提交 |
| 撤回审核被拒绝 | 该标记可能已有更新内容；重新读取并检查当前状态，避免覆盖后续要求 |
