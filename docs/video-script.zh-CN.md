# FacetCue for Blender 宣传视频制作脚本

适用版本 **0.5.2**。供动效设计、录屏、剪辑、配音人员及辅助制作工具使用；成片面向中文 Blender 用户、技术美术和 agent 工作流开发者。

核心表达：**在模型表面写 TODO，交给 Agent 去改，由你来验收。**

产品名使用 **FacetCue for Blender**，副标题使用“表面标注、Agent 修改与持久化审阅”。三条演示标记分别对应独立的自然语言问题：镜头 03–04 强调说明与三维锚点，镜头 07–08 展示批量读取和逐项修改，镜头 09–10 展示每条标记的状态与审核。保存 `.blend` 后可以接续这些记录；自动读取和修改由 Agent 配合已连接的建模工具完成。

## 成片规格与结构

| 项目 | 规格 |
| --- | --- |
| 主片 | 90 秒，3840 × 2160，60 fps，16:9，共 5400 帧 |
| 竖版 | 30 秒，1080 × 1920，60 fps，9:16，共 1800 帧 |
| 语言 | 普通话配音，简体中文字幕与画内说明 |
| 实际标识 | M0001、工具名、字段名、键帽和状态枚举保留原文 |

| 制作平台 | Blender 为主要动画和剪辑工具；真实操作在 Windows 录制 |
| 观看重点 | 标注位置、读取要求、实际修改、用户审核；安装细节见配套说明 |

MD 表示概念动效，RF 表示真实 Blender 或 agent 客户端录屏。概念段解释一件事，随后的录屏验证相应行为。主片不承担完整教程，删除、审核撤回、弹窗拖动、多行编辑和安装命令留在 [使用与实现说明](guide.zh-CN.md)。

## 必须保持真实的产品行为

- 插件负责注释及审核记录。几何修改由 agent 已有的 Blender 建模工具执行，完成后显式提交才出现蓝点。
- 任何看起来属于 Blender、插件或 agent 客户端的界面都使用真实录屏。允许裁切、放大、遮罩和说明性标线，不重绘控件、不替换状态、不生成假 JSON。抽象卡片与流程图不使用产品窗口样式。
- 标记附着于受支持的基础 Mesh。拍摄前确认没有启用的视口修改器或形态键；演示只做规定的对象平移和正比例缩放，不倒角、细分或改变拓扑。
- X-Ray 是 Alt+Z 的穿透显示。遮挡标记为 **40% 不透明度，即 60% 透明度**；主点、编号与状态蓝点保持一致，注释卡片默认折叠。
- “本机”只修饰注释连接；agent 可以使用外部模型服务。注释接口不接受代码执行请求，不能据此宣称所有建模工具也不执行代码，或整个 agent 工作流完全离线。
- 插件本体只用 Blender API 与标准库；MCP 配套服务仍需独立 Python 3.10+ 和 Python 依赖。许可证写全 **GPL-3.0-or-later**。
- 产品实拍使用已经验证的 Windows 环境，不用其他平台的录屏暗示完成了跨平台验证。构图中遮住绝对文件路径、连接令牌和实例 ID。
- 中文输入先确认候选词，再在组词结束后按 Enter 保存注释。不要把输入法选字和插件保存描述为必须由同一次 Enter 完成。

## 演示场景与状态连续性

### 模型和标记

使用中性灰设备柜，主体、前面板、侧把手和顶部盖板均为独立基础网格。柜体尺寸约 2.4 × 1.6 × 3 米，底部 Z=0；前方为 Y 负方向，右方为 X 正方向，上方为 Z 正方向。设置米制、单位比例 1，并让 SideHandle 的对象原点位于自身中心。

主构图从前右上方观察，能看见前面板、侧把手和顶盖。柜体需要能在绕到另一侧时遮住把手。建模阶段完成所有造型，再放注释。

| 标记 | 目标对象 | 正式注释原文 | 本片处理 |
| --- | --- | --- | --- |
| M0001 | FrontPanel | 把面板沿 Z 轴上移 0.12 米，保持尺寸不变。 | 修改、提交、通过 |
| M0002 | SideHandle | 把把手整体缩小 10%，位置不变。 | 修改、提交、打回 |
| M0003 | TopCover | 盖板沿 X 轴右移 0.05 米。 | 保留待处理，辅助展示多个标记 |

M0002 打回后的新要求为：“把手再沿 Z 轴上移 0.05 米，保持当前尺寸。”它只提出新的平移要求，不改变已经完成的缩放结果。

使用独立的演示文件和 Blender 用户配置，按顺序创建三条标记。首次放点前不要保留历史弹窗位置，保证镜头 03 的默认位置真实。颜色取自实际标记；编号、UUID、修订号以真实响应为准，不为了分镜去改写录屏数值。

### 拍摄阶段

下表适用于从新建开始、期间未额外编辑正文或状态的演示记录。缩放和平移本身不会增加注释 revision；新增正文修改会增加，重录时需重新核对。

| 阶段 | M0001 | M0002 | M0003 |
| --- | --- | --- | --- |
| 创建并确认后 | OPEN · revision 1 | OPEN · revision 1 | OPEN · revision 1 |
| 完成两项实际修改并提交后 | MODIFIED · revision 2 | MODIFIED · revision 2 | OPEN · revision 1 |
| 用户审核后 | RESOLVED · revision 3 | CHANGES_REQUESTED · revision 3 | OPEN · revision 1 |

保存“未放点”“三条待处理”“两条待审核”三个拍摄副本，重录时打开对应副本。不要在用户正在工作的场景中重置标记、批量修改状态或运行演示脚本。

## 视觉和声音规范

### 色彩与字体

| 用途 | 色值或来源 |
| --- | --- |
| 背景 | #08090A |
| 卡片表面 | #111214 |
| 细边框与连线 | 白色，8% 不透明度 |
| 主文字 | #F7F8F8 |
| 次文字 | #8A8F98 |
| 动效强调色 | #5E6AD2 到 #8B5CF6；每镜头只保留一个主要柔光区域 |
| 审核蓝点 | 从真实录屏取色 |
| 标记本体 | 从真实录屏取色，不用强调色覆盖产品颜色 |

中文使用 Noto Sans SC 或思源黑体，标题 Bold，字幕 Medium；拉丁文字使用 Inter，JSON 与标识符使用 JetBrains Mono。中文采用默认字距，中英文和数字之间适当留空格。

字幕每行最多 16 个字符，最多两行，底部居中，配约 60% 不透明度的深色底。4K 主片从 80–88 px 字号起试排，竖版从 48–56 px 起试排。视口紧凑输入框位于中下部时，字幕下移至安全区，键帽放侧边，避免盖住输入内容。英文工具名较长，放画内说明或独立卡片，不塞进字幕。

### 运动与转场

以下位移和圆角以 1920 × 1080 设计基准计，4K 输出按两倍缩放。

- 常规入场约 400 ms，也就是 60 fps 下约 24 帧；使用快速进入、缓慢落定的曲线，不出现可见回弹。
- 分句文字上移约 8 px，模糊从约 6 px 收到 0；错开约 60 ms，落到 60 fps 时间线上取 4 帧。
- 卡片轻微倾斜 8–12 度，镜头或整体画面在一镜内缓慢变化约 2%；避免持续晃动和过度景深。
- 键帽为扁平深色块与细边框，按下时缩到 0.94，再恢复。只在实际按键时闪出强调色。
- 真实录屏可装入圆角 16 px 的中性画框，再过渡到全画面。这只是影片边框，不仿造软件标题栏。
- 用圆点位置衔接动效与真实视口；剪切时对齐真实目标，生成画面不能覆盖真实点击结果。

参考中的 stiffness 180、damping 22 只作为手感描述，不能直接当作 Blender 通用动画参数。Blender 中用关键帧和 F 曲线拟合，无需增加弹簧求解依赖。

### 声音

采用克制的环境电子音乐，约 96 BPM。00:11 加入稀疏节奏，00:37 稍增加推动感，01:03 抬起层次，01:25 收束。关键声效包括落点、按键、过渡和审核通过，不持续堆叠提示音。旁白保持最清晰，声效与音乐在讲话时降低。

## 主片分镜

### 镜头 01 描述位置的困难

**时间 00:00–00:06 · 帧 1–360 · MD**

**画面：**深色背景上是一块轻微失焦的线框网格。抽象对话气泡进入，出现“左边那块面板……另一边的左边……”。细线划过文字，文字化成少量粒子，汇向表面的一点。对话气泡是概念图形，不模仿实际 agent 客户端。

**声音与衔接：**少量输入轻响，粒子汇聚时声音收束，接下一镜头的落点。字幕与气泡文字分处上下，避免互相遮挡。

**旁白：**“在三维里说清哪里，最难。”

### 镜头 02 产品出现

**时间 00:06–00:11 · 帧 361–660 · MD**

**画面：**线框设备清晰起来，一点落在前面板，扩散一次细环。点旁出现编号 M0001；产品名与“三维表面注释”淡入。圆点示意采用真实录屏取色。

**衔接：**落点位置对齐镜头 03 的目标表面位置。下一镜从尚未放点的真实视口开始，保留真实点击后生成标记的过程；不在真实画面上叠加假标记。

**旁白：**“那就直接指出来。”

### 镜头 03 放置并填写注释

**时间 00:11–00:22 · 帧 661–1320 · RF**

**实际操作：**在物体模式、实体显示、叠加层开启的视口中，按 Ctrl+Alt+Shift+A，点击前面板。紧凑注释框在中下部打开，填写“把面板沿 Z 轴上移 0.12 米，保持尺寸不变。”。先确认中文输入法候选，结束组词后按 Enter 保存。留出至少 1 秒展示弹窗关闭与标记出现。

**后期：**按实际按键时刻显示键帽。可剪去文字输入中段，不能跳过落点和保存结果。构图边角注明“基础 Mesh · 无启用修改器和形态键”。拍摄后正常保存 .blend；Enter 确认注释本身不等于保存文件。

**旁白：**“在网格表面，钉一条注释。编号、颜色和正文，随 .blend 文件保存。”

### 镜头 04 标记包含的信息

**时间 00:22–00:30 · 帧 1321–1800 · MD**

**画面：**镜头 03 的真实画面缩入深色画布。一个独立的结构示意展开四张小卡片：“编号 label”“正文 note”“状态 status”“修订号 revision”；第五张展示三角形、三个顶点、内部锚点与重心坐标。

**信息：**锚点卡标题为“三角面 · 重心坐标 · 拓扑指纹”，小字说明“拓扑改变需检查位置”。不编造 JSON、坐标或哈希值；需要数值时从实际响应提取。该段是数据结构说明，不做成插件面板。

**旁白：**“三角面与重心坐标，把注释关联到真实几何。”

### 镜头 05 遮挡和 X-Ray

**时间 00:30–00:37 · 帧 1801–2220 · RF**

**实际操作：**接入已放置三条标记的拍摄段，使用前右上方视角看到三个部件。缓慢绕转，让侧把手 M0002 被柜体遮挡并隐藏。固定视角，按 Alt+Z：它以 40% 不透明度重新显示；再按 Alt+Z 返回。

**后期：**显示 Alt、Z 键帽与“X-Ray”。字幕旁可短暂标注“60% 透明度”。X-Ray 下卡片默认折叠；画面外、对象隐藏和锚点失效不属于这次穿透显示演示。

**旁白：**“遮挡时隐藏，X-Ray 中半透明可见。”

### 镜头 06 本机注释通路

**时间 00:37–00:46 · 帧 2221–2760 · MD**

**画面：**四个抽象节点由左向右连接：“Agent 客户端 → stdio MCP → 本机接口 127.0.0.1 → Blender 主线程”。接口节点加小锁图形，光点沿连接线走过。下方依次强调 get_surface_annotations 和 submit_annotation_changes。

**屏幕字：**“本机注释通路”“令牌认证”“不接受代码执行”。另用细小但可读的一行注明“建模由现有 Blender 工具完成”。本机范围限定在这个注释接口，不把 agent 的模型推理、网络请求或其他建模工具画成这条通路的一部分。

**旁白：**“通过 MCP，读取注释。注释接口仅在本机，不接受代码执行请求。”

### 镜头 07 实际读取

**时间 00:46–00:55 · 帧 2761–3300 · RF**

**实际操作：**录制真实 agent 客户端与 Blender。发送：“读取 Blender 的表面注释，仅处理 M0001 和 M0002；M0003 留待后续。实际修改后提交完成说明，等待我审核。”客户端先调用 get_surface_annotations()，右侧面板显示最近 MCP 查询时间与条数。

**后期：**从实际响应中依次框选 note、status、revision、resolved.world_position 和 viewport 信息，选用两段可读裁切，避免整页 JSON 快速滚过。首次读取应为三条待处理记录，修订号按实际内容显示。绝对路径和实例 ID 遮罩；标记 UUID 可统一遮罩，M0001 等显示编号保留。

**画面前提：**演示只有三条注释、有效锚点和可用视口。通用读取仍有分页；没有视口时也能读注释和有效三维位置，不强行展示不存在的屏幕坐标。

**旁白：**“全文、位置和可见性，直接读取。无需截图，也不用先选物体。”

### 镜头 08 修改后提交审核

**时间 00:55–01:03 · 帧 3301–3780 · RF**

**实际操作：**agent 用已有 Blender 建模工具，将 FrontPanel 沿 Z 轴上移 0.12 米，并将 SideHandle 围绕自身中心均匀缩小至原尺寸的 90%，保持对象位置。真实完成两项后，使用修改前读取的 ID 和 revision 调用 submit_annotation_changes，分别写明实际改动。两条标记进入待审核。

**后期：**主体突出面板位移与标记跟随，把手改动保留一个短切镜。等待过程剪去，必要时仅将建模片段加速 4–8 倍并标注“过程节选”；成功提交与蓝点出现保持正常速度。下方常驻“建模由 agent 的 Blender 工具完成”。放大蓝点时保留主圆点原色和窄白边，不暗示整颗标记变蓝。

**旁白：**“建模工具改完，提交完成。蓝点亮起，等你审核。”

### 镜头 09 审核状态流转

**时间 01:03–01:10 · 帧 3781–4200 · MD**

**画面：**使用抽象流程图展示“待处理 OPEN → 已修改 · 待审核 MODIFIED → 已通过 RESOLVED”。从 MODIFIED 分支到“已打回 CHANGES_REQUESTED”，再经“按新要求修改并提交”返回 MODIFIED。打回不会直接变成 OPEN。

**修订号：**只对一个示例标记演示“新建 1 → 提交 2 → 审核 3”；使用独立的数字标签，不能把它伪装成真实 UI 或 JSON。再次提交会继续增加修订号，不在循环后重置。流程状态图标是影片说明，不代表插件还实现了其他颜色的状态点。

**旁白：**“让修改、反馈和验收，都回到标记上。”

### 镜头 10 在 Blender 中审核

**时间 01:10–01:20 · 帧 4201–4800 · RF**

**实际操作：**筛选“待审核”，按 Ctrl+Alt+Shift+→ 定位 M0001，展示视角围绕注释点及面板“Agent 修改说明”。按 Ctrl+Alt+Shift+Enter 通过，蓝点消失。再定位已完成提交的 M0002，按 Ctrl+Alt+Shift+Backspace，写下“把手再沿 Z 轴上移 0.05 米，保持当前尺寸。”，按 Enter 确认打回。

**后期：**分为“定位 / 通过 / 打回”三个短切镜，键帽逐次出现。可剪去输入中段，保留中文选字结束后的保存动作。通过和打回后，记录会离开待审核筛选；最后短切到“已打回”筛选展示 M0002。干净演示中此时 revision 为 3，不添加 revision: 2 的假响应。

**旁白：**“逐条定位，满意就通过。不满意，补充要求，打回重做。”

### 镜头 11 渲染保持干净

**时间 01:20–01:25 · 帧 4801–5100 · RF 加 MD 转场**

**实际画面：**切回“全部”筛选，以前右上方视角显示标记；与同机位、同一修改后模型的真实渲染结果进行擦除对照。需要展示 F12 时，剪去实际渲染等待，使用真实完成的画面，不把等待压缩成产品响应速度承诺。

**衔接：**渲染画面缩回深色画布。摄影文件不加入影片用标记几何，插件的圆点与注释框自然不会进入 F12 渲染。

**旁白：**“标记只在视口显示，不进入渲染。”

### 镜头 12 片尾

**时间 01:25–01:30 · 帧 5101–5400 · MD**

**画面：**产品名 FacetCue for Blender、版本 0.5.2 与副标题“表面标注 · Agent 修改 · 持久化审阅”出现。规格保留“Blender 4.2+”“GPL-3.0-or-later”，下一行写“安装：Blender ZIP + 独立 Python MCP”。最后至少 2 秒保持静止。

**行动引导：**“指出位置 · 交给 Agent · 由你验收”“安装与使用说明见项目文档”。有真实已发布地址后再放链接；没有地址时使用这句文字，不制作假链接或二维码。不要将“插件本体无第三方依赖”简化成整套 MCP 无需依赖。

**旁白：**“指出位置，交给 Agent。由你验收。”

## 配音与字幕

普通话、成年中性声线，清楚、克制。以约每秒 4–4.5 个中文字的感觉试读，英文工具名按实际发音留时，镜头间保留短暂停顿，不用变速硬塞配音。Agent、MCP、X-Ray 用英文读；.blend 读作“点 blend”。

## Blender 制作方案

### 文件组织与渲染

| 制作文件 | 用途 |
| --- | --- |
| demo_model.blend | 模型和真实标记，用于录屏；不加入影片用圆点对象 |
| motion_graphics.blend | 片头、信息结构、连接链路、审核流程和片尾 |
| edit_master.blend | 90 秒横版的录屏、渲染、字幕和声音时间线 |
| edit_vertical.blend | 30 秒竖版重新构图，字幕与图形单独排版 |

这些是制作阶段的文件约定，本次脚本交付不包含已制作的动画、录屏或音频。MD 图形放在独立集合中；每个镜头有自己的摄像机或场景。先按低分辨率预览确认节奏，再输出 4K60 帧序列。需要叠加的图形输出透明背景帧序列，最终在视频序列编辑器组合。

真实录屏和 F12 渲染来自 demo_model.blend。模型渲染不需要手动删除标记；插件没有可渲染的标记几何。不能将 motion_graphics.blend 中的影片用点当成这个结论的证明画面。

### 动效搭建

卡片与键帽用简单平面或浅厚度几何，文字使用 Blender 文本对象，细线用曲线。信息图优先用正交摄像机保证字号稳定；需要轻微空间感时，只旋转卡片根节点，不让文字产生明显透视压缩。

一个典型 24 帧入场可以按第 1 帧隐藏并偏移、第 16 帧接近目标、第 24 帧完全落定来安排。透明度或合成混合量同时进入；第 16 帧已经接近最终尺寸，避免视觉反弹。文字模糊可单独渲染后合成，不模糊真实录屏的按钮与正文。

标记数据示意、MCP 连接与审核箭头由设计师在 Blender 中准确搭建。跟随模型的影片用点保持面向摄像机，并校正屏幕尺寸；状态蓝点与主点一起运动。需要示意 40% 不透明度时，先合成整组点与数字，再统一降低到 0.4，避免多层透明片叠加后过实。

片头采用前右上方机位，约 50 mm 镜头作为起点，小幅推近即可。对应 RF 段使用相近视角。真实审核段的定位由插件触发，不用摄像机动画替代产品行为。

## 录屏安排

1. 在独立演示配置中启用一份插件，确认“Agent 连接已就绪”。使用简体中文界面和深色主题，把 UI 缩放调到画面中文字清晰可读；可从 1.25 起试。保留 3D 视口及 FacetCue for Blender 面板，减少无关编辑区域。
2. 设置 4K60 录制，先试拍鼠标、输入框和中文 IME。需要按键时间参考时，仅记录快捷键事件，不记录正文；不要使用记录所有文字的全局键盘日志。
3. 录制镜头 03 的无标记起始状态，再创建其余两条并保存待处理副本。镜头 03 保持视角稳定以匹配片头落点。
4. 录制镜头 05 的绕转与 X-Ray，确认侧把手的遮挡是真实几何造成，且不透明度变化可辨。
5. 配置好两个必要通路：本插件的注释 MCP，以及已有的 Blender 建模工具。客户端字体调大，完成镜头 07、08 的真实读取、两项修改与提交。
6. 保存两条待审核副本，再录制镜头 10 的通过与打回。查看实际修订号，确认 M0003 保留待处理。
7. 切回全部筛选，录制视口与同机位真实渲染，完成片尾衔接。
8. 每段录制三个可选 take，头尾各留 2 秒；可按镜头号命名。重录使用副本，不通过后期伪造结果。完整流程确认后再遮罩路径、实例 ID 与不需展示的 UUID。
